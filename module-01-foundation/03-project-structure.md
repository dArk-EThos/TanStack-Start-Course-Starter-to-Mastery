## Overview

Understanding your project structure is crucial for productive development. TanStack Start follows conventions that make sense once you understand the reasoning behind them.

> [!NOTE]
> TanStack Start uses a **convention-over-configuration** approach. Following the standard structure gives you powerful features automatically.

---

## Directory Structure

Here's the complete structure of a typical TanStack Start project:

```
my-tanstack-app/
├── 📁 node_modules/         # Dependencies (don't touch!)
├── 📁 public/               # Static assets served as-is
│   ├── favicon.ico
│   ├── robots.txt           # SEO: Crawler instructions
│   └── images/              # Public images
├── 📁 src/                  # Your application code
│   ├── 📁 routes/           # File-based routes (IMPORTANT!)
│   │   ├── __root.tsx       # Root layout
│   │   ├── index.tsx        # Home page
│   │   └── about.tsx        # About page
│   ├── 📁 components/       # Reusable React components (you create this)
│   ├── 📁 lib/              # Utility functions & helpers (you create this)
│   ├── 📁 styles/           # Global styles (you create this)
│   ├── router.tsx           # Router configuration
│   ├── client.tsx           # Client entry point
│   └── server.tsx           # Server entry point (auto-generated)
├── 📁 .vinxi/               # Build output (generated, ignore)
├── 📄 app.config.ts         # App configuration
├── 📄 package.json          # Dependencies & scripts
├── 📄 tsconfig.json         # TypeScript config
├── 📄 tailwind.config.ts    # Tailwind config (if using Tailwind)
├── 📄 .eslintrc.cjs         # ESLint config
├── 📄 .prettierrc           # Prettier config
├── 📄 .gitignore            # Git ignore rules
└── 📄 README.md             # Project documentation
```

## The src/ Directory

This is where all your application code lives. Let's explore each part:

### 1. `src/routes/` - The Heart of Your App

**Purpose**: Define your application's routes using file-based routing.

**Key Points**:

- **File names = URL paths** (with some special conventions)
- Each file exports a `Route` object
- Auto-code splitting happens here
- Routes can have loaders, components, and more

**Example Structure**:

```
src/routes/
├── __root.tsx              # Layout for all routes
├── index.tsx               # /
├── about.tsx               # /about
├── blog/
│   ├── index.tsx           # /blog
│   ├── $postId.tsx         # /blog/:postId (dynamic)
│   └── new.tsx             # /blog/new
└── dashboard/
    ├── _layout.tsx         # Layout (doesn't add to URL)
    ├── index.tsx           # /dashboard
    └── settings.tsx        # /dashboard/settings
```

We'll explore routing in detail in Module 2!

### 2. `src/components/` - Reusable Components

**Purpose**: Store React components used across multiple routes.

> [!TIP]
> You need to create this directory yourself - it's not generated by default.

**Example Structure**:

```
src/components/
├── ui/                     # UI components (buttons, inputs, etc.)
│   ├── button.tsx
│   ├── input.tsx
│   └── card.tsx
├── layout/                 # Layout components
│   ├── header.tsx
│   ├── footer.tsx
│   └── sidebar.tsx
└── features/               # Feature-specific components
    ├── auth/
    │   ├── login-form.tsx
    │   └── signup-form.tsx
    └── blog/
        ├── post-card.tsx
        └── post-list.tsx
```

**Example Component**:

```typescript
// src/components/ui/button.tsx
import { type ReactNode } from "react";

interface ButtonProps {
  children: ReactNode;
  onClick?: () => void;
  variant?: "primary" | "secondary";
}

export function Button({
  children,
  onClick,
  variant = "primary",
}: ButtonProps) {
  return (
    <button
      onClick={onClick}
      className={`px-4 py-2 rounded ${
        variant === "primary"
          ? "bg-blue-500 text-white"
          : "bg-gray-200 text-gray-800"
      }`}
    >
      {children}
    </button>
  );
}
```

### 3. `src/lib/` - Utilities and Helpers

**Purpose**: Shared utilities, API functions, constants, and helpers.

**Example Structure**:

```
src/lib/
├── api/                    # API/Server function definitions
│   ├── users.ts
│   ├── posts.ts
│   └── auth.ts
├── utils/                  # Utility functions
│   ├── date.ts
│   ├── string.ts
│   └── validation.ts
├── hooks/                  # Custom React hooks
│   ├── use-auth.ts
│   └── use-media-query.ts
├── types/                  # TypeScript type definitions
│   ├── user.ts
│   └── post.ts
└── constants.ts            # App-wide constants
```

**Example API File**:

```typescript
// src/lib/api/users.ts
import { createServerFn } from "@tanstack/start";
import { z } from "zod";

const getUserSchema = z.object({
  id: z.string(),
});

export const getUser = createServerFn({ method: "GET" })
  .inputValidator(getUserSchema)
  .handler(async ({ data }) => {
    // Server-only code
    const user = await db.user.findUnique({
      where: { id: data.id },
    });
    return user;
  });
```

### 4. `src/styles/` - Global Styles

**Purpose**: Global CSS, Tailwind directives, and style utilities.

**Example Structure**:

```
src/styles/
├── globals.css             # Global styles & Tailwind imports
├── variables.css           # CSS custom properties
└── fonts.css               # Font imports
```

**Example `globals.css`**:

```css
/* src/styles/globals.css */
@tailwind base;
@tailwind components;
@tailwind utilities;

@layer base {
  :root {
    --background: 0 0% 100%;
    --foreground: 222.2 84% 4.9%;
  }

  * {
    @apply border-border;
  }

  body {
    @apply bg-background text-foreground;
  }
}
```

### 5. `src/router.tsx` - Router Configuration

**Purpose**: Configure your TanStack Router instance.

```typescript
// src/router.tsx
import { createRouter } from "@tanstack/react-router";
import { routeTree } from "./routeTree.gen";

export function getRouter() {
  const router = createRouter({
    routeTree,

    // Router options
    defaultPreload: "intent", // Preload on hover
    defaultPreloadDelay: 50, // 50ms hover delay
    scrollRestoration: true, // Restore scroll position

    // Default pending component
    defaultPendingComponent: () => <div>Loading...</div>,
  });

  return router;
}

// TypeScript: Export router type for use elsewhere
export type Router = ReturnType<typeof getRouter>;

// Augment TanStack Router types
declare module "@tanstack/react-router" {
  interface Register {
    router: Router;
  }
}
```

**Key Configuration Options**:

| Option                | Description                       | Default |
| --------------------- | --------------------------------- | ------- |
| `defaultPreload`      | When to preload routes            | `false` |
| `defaultPreloadDelay` | Delay before preloading (ms)      | `50`    |
| `scrollRestoration`   | Restore scroll on navigation      | `false` |
| `defaultPendingMs`    | Show pending component after (ms) | `1000`  |

### 6. `src/client.tsx` - Client Entry Point

**Purpose**: Mount your React app to the DOM (runs in browser).

```typescript
// src/client.tsx
import { createRoot } from "react-dom/client";
import { StartClient } from "@tanstack/start";
import { getRouter } from "./router";

const router = getRouter();

const rootElement = document.getElementById("root")!;

if (!rootElement.innerHTML) {
  const root = createRoot(rootElement);
  root.render(<StartClient router={router} />);
}
```

> [!IMPORTANT]
> Don't put server-only code here! This file runs in the browser.

## Route Files

Every route file follows a specific pattern:

### Basic Route File Structure

```typescript
// src/routes/about.tsx
import { createFileRoute } from "@tanstack/react-router";

// 1. Export the Route object
export const Route = createFileRoute("/about")({
  // 2. Optional: Load data before rendering
  loader: async () => {
    return {
      title: "About Us",
      description: "Learn about our company",
    };
  },

  // 3. Define the component
  component: AboutComponent,
});

// 4. Implement the component
function AboutComponent() {
  const { title, description } = Route.useLoaderData();

  return (
    <div>
      <h1>{title}</h1>
      <p>{description}</p>
    </div>
  );
}
```

### Root Route (`__root.tsx`)

Special route that wraps all other routes:

```typescript
// src/routes/__root.tsx
import {
  Outlet,
  createRootRoute,
  ScrollRestoration,
} from "@tanstack/react-router";
import { TanStackRouterDevtools } from "@tanstack/router-devtools";
import { Scripts } from "@tanstack/start";

export const Route = createRootRoute({
  component: RootComponent,
});

function RootComponent() {
  return (
    <html lang="en">
      <head>
        <meta charSet="UTF-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1.0" />
        <title>My App</title>
        <link rel="stylesheet" href="/styles/globals.css" />
      </head>
      <body>
        {/* Your app content */}
        <Outlet />

        {/* Required for client-side JavaScript */}
        <Scripts />

        {/* Restore scroll position on navigation */}
        <ScrollRestoration />

        {/* Development tools */}
        <TanStackRouterDevtools position="bottom-right" />
      </body>
    </html>
  );
}
```

**Key Components**:

- `<Outlet />`: Renders child routes
- `<Scripts />`: Injects client-side JavaScript (required!)
- `<ScrollRestoration />`: Restores scroll position on back/forward
- `<TanStackRouterDevtools />`: Development tools (only in dev)

## Generated Files

### `src/routeTree.gen.ts` - Auto-Generated Route Tree

**DO NOT EDIT THIS FILE!** It's automatically generated from your route files.

```typescript
// src/routeTree.gen.ts (example)
import { rootRoute } from "./routes/__root";
import { indexRoute } from "./routes/index";
import { aboutRoute } from "./routes/about";

const routeTree = rootRoute.addChildren([indexRoute, aboutRoute]);

export { routeTree };
```

**When is it generated?**

- When you run `pnpm dev`
- Whenever you add/remove/rename route files
- When you run `pnpm build`

> [!WARNING]
> Add `routeTree.gen.ts` to `.gitignore`? **No!** Some teams commit it for better type checking in CI.

## Best Practices

### 1. **Keep Routes Focused**

```typescript
// ✅ Good: Routes delegate to components
export const Route = createFileRoute("/blog/$postId")({
  component: () => <BlogPostPage />, // Component handles logic
});

// ❌ Bad: Too much logic in route file
export const Route = createFileRoute("/blog/$postId")({
  component: () => {
    // 200 lines of component code...
  },
});
```

### 2. **Use Barrel Exports**

```typescript
// src/components/ui/index.ts
export { Button } from "./button";
export { Input } from "./input";
export { Card } from "./card";

// Now you can import like:
import { Button, Input, Card } from "@/components/ui";
```

### 3. **Organize by Feature**

For larger apps, organize by feature instead of type:

```
src/
├── features/
│   ├── auth/
│   │   ├── components/
│   │   ├── hooks/
│   │   ├── api/
│   │   └── types.ts
│   ├── blog/
│   │   ├── components/
│   │   ├── hooks/
│   │   └── api/
│   └── dashboard/
│       ├── components/
│       └── hooks/
└── shared/              # Shared across features
    ├── components/
    └── hooks/
```

### 4. **Type-Safe Environment Variables**

```typescript
// src/lib/env.ts
import { z } from "zod";

const envSchema = z.object({
  DATABASE_URL: z.string().url(),
  API_KEY: z.string(),
  NODE_ENV: z.enum(["development", "production", "test"]),
});

export const env = envSchema.parse(process.env);

// Usage:
import { env } from "@/lib/env";
console.log(env.DATABASE_URL); // Fully typed!
```

## Recommended Structure for Large Apps

As your app grows, consider this structure:

```
src/
├── routes/              # File-based routes
├── features/            # Feature modules
│   ├── auth/
│   │   ├── components/
│   │   ├── hooks/
│   │   ├── api.ts
│   │   └── types.ts
│   ├── blog/
│   └── dashboard/
├── shared/              # Shared utilities
│   ├── components/
│   │   └── ui/         # ShadCN components
│   ├── hooks/
│   ├── utils/
│   └── types/
├── lib/
│   ├── api/            # API client setup
│   ├── db/             # Database client
│   └── env.ts          # Environment config
├── styles/
│   └── globals.css
├── router.tsx
└── client.tsx
```
